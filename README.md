# xss-wargame
reflected xss

## 문제 개요와 목표

아이디를 입력하면 존재 여부를 `alert()` 팝업으로 알려주는 간단한 사이트입니다.
아이디 입력창에 값을 넣어서 원래 있던 `alert()` 외에 추가로 `alert()`가
한 번 더 실행되도록 만들고 `FLAG`를 획득하세요.

## 실행 방법

터미널로 실행 후

크롬 브라우저에서 `http://127.0.0.1:5000` 접속

## 취약점 종류와 위치

종류:
Reflected XSS

위치:
`app.py`의 `check()` 함수에서 사용자 입력을 전달하며, `RESULT_HTML` 템플릿의 `{{ username|safe }}` 부분에서 XSS가 발생

```python
alert("'{{ username|safe }}' 는 존재하지 않는 사용자입니다.");
```

URL의 `username` 파라미터 값이 검증 없이 그대로 이 스크립트에 삽입됩니다.

## 왜 취약한가

Jinja2는 `{{ }}`로 값을 출력할 때 기본적으로 `<`, `>`, `"`, `'` 등의 특수문자를
자동으로 안전하게 변환해줍니다. 그런데 `{{ username|safe }}`처럼 `|safe` 필터를
쓰면 이 자동 변환이 적용되지 않습니다.

게다가 이 값은 단순한 HTML 텍스트가 아니라 JS 문자열 내부에 그대로
삽입됩니다.

```javascript
alert("'{{ username|safe }}' 는 존재하지 않는 사용자입니다.");
```

그래서 큰따옴표(`"`)가 포함된 값을 입력하면 원래 있던 JS 문자열을
그 자리에서 끊어버리고, 세미콜론(`;`)으로 이어서 새로운 JS 문장을
삽입할 수 있습니다. 뒤에 남는 코드는 `//`로 주석 처리해버리면 됩니다.

예시:
```text
x"); alert(document.cookie); //
```
...

```javascript
alert("'x"); alert(document.cookie); //' 는 존재하지 않는 사용자입니다.");
```

원래 있던 `alert()` 호출과 새로 삽입한 `alert()` 호출이 각각 따로 실행되면서,
JS 문자열에서 발생하는 Reflected XSS를 확인할 수 있습니다.

## 방어 방법

`|safe`만 지우면 특수문자가 자동으로 변환되어 문자열 탈출 공격을 방어할 수 있습니다.

```jinja2
{{ username }}
```

다만 실제 서비스에서는 애초에 사용자 입력을 JavaScript 코드 안에 직접 넣지
않는 게 가장 안전합니다.
